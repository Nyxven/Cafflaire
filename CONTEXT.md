## What this is
**Cafflaire**: a mobile + desktop coffee-ordering webapp (hackathon MVP). Customers build their own coffee in a barista-style builder (live SVG cup, caffeine/sweetness/calorie stats, running price), add several drinks to a basket, then check out for pickup or delivery (cash). PHP ₱, integer centavos. Hackathon pitch angle: AI-assisted MVP focused on secure, simple user authentication.

**What the builder does now**
- **Espresso:** hold the button until the bar fills = ONE shot (1.1 s); keep holding = next shot; early release = nothing added/charged; quick tap (<0.26 s) or Enter/Space = exactly one shot; max 4. Machine shakes (CSS), shows a progress display + a mini cup that fills; a nozzle streams into the main cup, a dark espresso layer rises in the cup while you hold, then ding + sparkle + `+₱` pop. Rules live in `src/lib/brew.ts` (`createBrew`) and are unit-tested.
- **Milk:** pitcher swings in, tilts, stream falls, milk rises in the cup, pitcher leaves, cup ripples. Pour length depends on base + size (`milkPourMs`, 0.8–1.8 s). One pour at a time (taps during a pour are ignored). Card pitcher icon tips while pouring.
- **Syrup:** pump head moves down/up; a droplet in the syrup colour flies from the spout to the cup; 420 ms cooldown per bottle (mashing/holding can't over-add); max 5.
- **Matcha:** scoop swings over the cup and powder falls; one scoop at a time. **Toppings:** drizzles flow as a ribbon, others arc in; they settle onto the cup (drop-in); one pending per topping. **Ice** cubes drop in when you pick Iced; hot-milk foam grows in.
- **Steps:** content slides with direction (AnimatePresence), progress bar + "Step n of 7", completed steps get a ✓, pill row auto-scrolls on phones, cup shine on Next; reaching Review plays a "ta-da" (chime, big sparkle, cup lifts) and shows an "Order up!" ticket (name, size, ingredient chips, price) above the existing stats/price breakdown.
- **Add to basket:** confirmation card with animated cup, ✓ stamp, name/size/ingredients/stats/price; "View basket" is focused so checkout is one press away. Uses a snapshot, so it doesn't flicker when the builder resets.
- **Safety:** all delayed callbacks are tracked and cleared on finish/reset/unmount (`clearPending`), leaving a step cancels an in-progress brew, extra shots can't exceed 4 even with drag-and-drop mid-brew. Pricing, validation, catalog and store were NOT changed.
- **Reduced motion:** flights/streams/overlays/shake are off; things land instantly (so scoops/toppings behave like plain steppers); hold-to-brew still works with the progress bar. Variants/initial values are identical on server and client (a hydration warning found during testing was fixed).

## Security model
Passwords: scrypt hashes. OTP: hashed, 6 digits, 10-min expiry, 5 attempts, 30s resend. Emails/session tokens/OTP identifiers: deterministic AES-GCM (lookups work). Names/phones/addresses/notes/IP/user-agent: randomized AES-GCM. Key = `DATA_ENCRYPTION_KEY` (env only; falls back to derivation from `BETTER_AUTH_SECRET`). Losing the key makes data unreadable. Rate limits on sign-up/sign-in/OTP routes (DB storage). Profile: change password, sign out all devices, delete account. Pre-OTP test users should be deleted (`delete from "user";`). Taste answers (`user_prefs.data`) are encrypted too and cascade-delete with the account.

## Gotchas learned
No dynamic JSX tags like `<Icon[x] />` (assign to a capitalised variable first) · framer `layoutId` pills need a shared `LayoutGroup` id · `template.tsx` (not `layout.tsx`) is what re-mounts per navigation for page transitions · hand-written drizzle migrations need a matching `_journal.json` entry (and ideally a snapshot) · `sh` has no brace expansion (use bash for mkdir -p {a,b}) · never pipe `next build` into `head` (corrupts .next) · Next 15 `params`/`searchParams` are Promises · page files may only export Next's allowed names · sticky inside CSS grid on mobile needs flex-col · Better Auth does NOT auto-send an OTP on a blocked unverified login (UI requests one) · rate limiting only applies via `auth.handler`, not `auth.api.*`.
